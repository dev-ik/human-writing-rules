# Human Writing Rules 1.1.0

This compatible 1.x release expands platform coverage, TypeScript CLI support,
agent-led intake, tone guidance, and bilingual repository documentation while
preserving the stable `1.0.0` normative RFC profile.

## What changed

- The TypeScript CLI is now the primary user entry point for diagnostics,
  registry/object discovery, module resolution, intake questions, and run
  planning.
- Agent-led intake is available through bounded adaptive question rounds and
  the `runs questions` command.
- Dzen, GitHub, vc.ru, DEV Community, and newsletter platform modules are
  registered as active runtime objects.
- Habr guidance now covers publication metadata, hubs, tags, difficulty,
  translations, news framing, and preview checks more explicitly.
- The content model now states explicitly that platform selection never grants
  a new topic, evidence standard, tone, author expertise, or first-person
  claims.
- Human-signal rules and reviewer checks now call out stock AI-like setup,
  hype, and transition phrases as text to replace with concrete actors,
  constraints, consequences, source boundaries, or reader decisions.
- Source-integrity rules now distinguish legitimate originality from close
  paraphrase, hidden source dependence, and AI-detector evasion.
- Tone profiles now include `blogger`, `developer`, `writer`, `screenwriter`,
  and `amateur`, with guardrails that tone never creates unsupplied authority,
  expertise, experience, or scenes.
- The reviewed example catalog now contains 21 examples covering all 11
  registered topics and all 11 registered platform families.
- The repository includes English and Russian README navigation and
  `.gitattributes` language-statistics overrides for Python compatibility
  tooling.

## Compatibility

This release is additive. It does not change RFC-0001 through RFC-0006, active
schema/protocol compatibility, or existing public value mappings. Existing
consumers can keep using the stable `1.0.0` specification revision.

For reproducible resolution, pin both the `spec_revision` and the generated
registry `source_revision`.

## Included

- 60 active runtime objects;
- 11 platform families;
- 21 reviewed examples;
- 8 tone profiles;
- TypeScript CLI parity coverage for the native command set;
- offline release verification through the manifest-defined gates.

## Important boundaries

The bundled reference tooling still uses Python as a temporary compatibility
backend for unported commands and release validators. The stable specification
status does not claim full implementation conformance for every writing engine.

The internal stability review remains non-independent. This release does not
include public comparative model-quality results or inter-rater reliability
evidence.

## Verification

```sh
npm run release:verify
```

The command runs the manifest-defined release gates offline. The optional live
provider adapter remains opt-in and requires credentials supplied through the
environment.
