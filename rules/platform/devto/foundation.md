# DEV Community

Load `platform.blog.foundation`.

- Treat the artifact as a developer community post: tutorial, explanation, project note, release note, career reflection, or discussion prompt.
- Make prerequisites explicit: language, runtime, framework, package versions, operating assumptions, account requirements, and prior knowledge.
- Test code examples or mark them as illustrative. Include expected output, failure modes, cleanup, and links to complete source when useful.
- Keep beginner-friendly pacing without hiding tradeoffs, security implications, accessibility constraints, or production-readiness limits.
- Choose tags by actual topic and reader path, not reach. Do not tag unrelated languages, frameworks, or communities.
- If the post adapts existing docs, a repository README, a talk, or another article, credit the source and preserve license or canonical-link expectations.
- For open-source posts, distinguish what is released, experimental, planned, deprecated, unsupported, or looking for contributors.
- For opinions and career posts, separate personal experience from general advice and do not invent workplace stories.
- Verify Markdown rendering, syntax highlighting, embeds, cover image crop, canonical URL, series membership, comments context, and accessibility metadata before handoff.
