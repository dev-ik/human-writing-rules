# Human Writing Rules 1.1.1

This patch release makes the existing editing rules easier to apply and fixes
CLI version reporting. The stable `1.0.0` normative profile is unchanged.

## What changed

- Added a practical editing guide with six Russian and English examples. It
  shows how to remove empty setup, simplify bureaucratic wording, correct an
  unsupported promise, and preserve a material limitation. Two examples show
  when clear prose should remain unchanged.
- Clarified preservation of the supplied author's voice, comparison of meaning
  across revisions, and the requirement to tie style findings to a concrete
  reader problem. Review guidance now explicitly addresses when to stop editing.
- Fixed `hwr --version` and top-level help to report the installed distribution
  version from `package.json`, rather than the specification revision. A
  regression test checks both outputs outside the repository and without Python
  on PATH.
- Updated English and Russian README navigation, related guides, and repository
  positioning around evidence boundaries, review contracts, and audit records.

## Compatibility

Existing configs, active object IDs, schemas, JSON envelopes, and workflow
commands retain their 1.x contracts. The distribution version is `1.1.1`;
`doctor` continues to report specification revision `1.0.0`.

The six editing exercises are informative examples. They are separate from the
catalog of 21 reviewed publication examples and do not establish measured
improvements in model output quality.

The internal stability review remains non-independent. Unported commands and
release validators still require the Python compatibility backend.

## Verification

```sh
npm ci
npm run verify
```

Verification includes TypeScript typechecking and CLI tests, Python unit tests,
and the eight manifest-defined release gates. CI runs the suite on Node.js 20
with Python 3.9 and 3.12. Core verification remains offline after dependency
installation; live provider adapters require explicit opt-in.
