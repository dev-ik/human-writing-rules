# Support

Use GitHub issues in `dev-ik/human-writing-rules` for reproducible bugs,
documentation gaps, interoperability questions, and scoped rule proposals.

Before opening an issue:

1. run `npm run release:verify`;
2. record the distribution version, specification revision, and registry
   source revision;
3. reduce the report to synthetic or public material;
4. separate observed behavior from the desired change;
5. state whether the issue affects Editorial Core, Editorial Visual, Benchmark,
   or reference tooling only.

Do not use a public issue for credentials, private sources, personal data, or
unpublished vulnerability details. Follow [`SECURITY.md`](SECURITY.md) instead.

The project does not provide guaranteed response times, professional editorial
approval, or emergency medical, legal, financial, or safety advice.
