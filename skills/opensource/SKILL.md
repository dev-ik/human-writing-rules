# Opensource Skill

Read the repository, documentation, license, releases, issues, security guidance, examples, and limitations. Explain the problem addressed, not only the feature list.

## Workflow

1. Identify the repository, maintained version, license, and project status.
2. Verify claimed capabilities in code, documentation, examples, or reproducible use.
3. Distinguish maintainer goals, implemented behavior, roadmap, and community interpretation.
4. Explain installation or adoption cost when relevant.
5. Include compatibility, maintenance, security, and contribution limitations.
6. Disclose the author's relationship to the project.

Do not infer adoption, production readiness, security, or maintainer commitment from stars, a polished README, or an announcement alone.

Architecture diagrams and code screenshots must match the referenced revision. Generated visuals may represent the problem conceptually but must not imply project UI or integrations that do not exist.
